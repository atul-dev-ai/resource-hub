# Contributing Guide

Thank you for your interest in contributing to this project.
This platform is built for students to share academic resources in a structured and reliable way. To maintain quality and consistency, all contributions must follow the rules below.

---

## 🚨 Important Rules

* Do not copy or rebrand this project as your own.
* Always give proper credit when using or referencing this project.
* Contributions that violate structure, quality, or purpose will be rejected.
* Spam, low-quality uploads, or irrelevant content are strictly prohibited.

---

## 🧩 What You Can Contribute

You are welcome to contribute in the following areas:

* Bug fixes
* UI/UX improvements
* Performance optimization
* New features (must be discussed first)
* Documentation improvements

---

## ❌ What NOT to Do

* Do not submit unrelated features
* Do not break existing functionality
* Do not submit untested code
* Do not upload random or low-quality academic content
* Do not change core structure without discussion

---

## 🛠 Development Setup

1. Fork the repository
2. Clone your fork

   ```
   git clone https://github.com/your-username/repo-name.git
   ```
3. Install dependencies

   ```
   npm install
   ```
4. Run the development server

   ```
   npm run dev
   ```

---

## 🌿 Branching Strategy

* Use clear branch names:

  * `feature/add-upload-filter`
  * `fix/login-validation`
  * `refactor/dashboard-layout`

* Never push directly to `main` branch

---

## 🔁 Pull Request Process

1. Create a new branch
2. Make your changes
3. Test everything properly
4. Commit with clear message
5. Push to your fork
6. Open a Pull Request

---

## ✅ Pull Request Rules

* PR must solve a clear problem
* PR description must explain:

  * What you changed
  * Why you changed it
* UI changes must include screenshots
* Large changes must be discussed before implementation

---

## 🔍 Code Quality Standards

* Follow clean and readable code practices
* Use meaningful variable and function names
* Avoid unnecessary complexity
* Maintain consistent formatting
* Write reusable components

---

## 🔐 Security Guidelines

* Do not expose secrets or API keys
* Validate all inputs properly
* Follow authentication and authorization rules strictly

---

## 🧪 Testing

* Test your code before submitting
* Ensure no existing feature is broken
* Fix all errors and warnings

---

## 💬 Communication

* Be respectful and professional
* Discuss major changes before implementation
* Ask questions if something is unclear

---

## ⚖️ License & Credit

By contributing, you agree that your contributions will be part of this project.

You must not reuse or distribute this project without proper attribution to the original author.

---

## 🚀 Final Note

This is not just a practice project.
This is a structured academic platform.

Low-quality contributions will be rejected without discussion.
